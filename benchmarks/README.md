# scBOA External Concordance and Method Benchmark

This repository contains the tabular outputs and reproducibility records used to evaluate
scBOA against external annotations, established data-driven clustering-parameter selection
methods, and alternative optimization strategies.

The analyses were designed to address three related questions:

1. Does the scBOA internal objective show concordance with external biological annotations
   across multiple tissues?
2. How does scBOA compare with existing methods for selecting representation, clustering,
   resolution, or cluster-number parameters?
3. Are the observed optimizer-level results reproducible across independent random seeds?

A fourth, supporting analysis is also included: a **partial reference-mismatch benchmark**
(B-lineage hold-out) that characterises scBOA behaviour when the annotation reference does
not cover all populations present in the data.

## 3. Analysis 1 — Objective-to-ground-truth concordance

**Script:** `objective_to_facs_concordance_1argu.py`
**Output:** `data/objective_concordance/{pbmc, baron_pancreas, litvinukova_heart}/`

### 3.1 Purpose

This analysis tests whether scBOA's internal objective tracks external biological quality,
or whether apparent concordance is a **cluster-count artefact**. It re-runs every Stage-1
Bayesian-optimization trial on an externally annotated dataset, computes six external
ground-truth metrics per trial, and audits the internal↔external correlation under three
regimes: raw, partial (controlling cluster count), and doubly-partial (controlling cluster
count **and** resolution).

### 3.2 Inputs

| Flag | Purpose |
|---|---|
| `--data_dir` | 10x MTX v3 triplet (`matrix.mtx.gz`, `features.tsv.gz`, `barcodes.tsv.gz`) |
| `--ground_truth` | CSV with `cell_id` + ground-truth label column (column names inferred automatically) |
| `--model_path` | CellTypist `.pkl` model matching the tissue |
| `--yield_csv` | Stage-1 `*_yield_scores_report.csv` from a scBOA BO run; one row per trial with `n_hvg`, `n_pcs`, `n_neighbors`, `resolution` and internal-objective columns |
| `--output_dir` | Destination for all CSVs and figures |

The appropriate `map_to_*_broad()` label collapser is selected automatically from
`--model_path` and `--data_dir`.

### 3.3 Per-trial procedure

For each of the 90 trials in `--yield_csv`:

1. Rebuild the exact Stage-1 preprocessing chain from the trial's hyperparameters and record
   the resulting Leiden cluster count.
2. Run CellTypist on the trial's preprocessed matrix → per-cell predicted label + confidence.
3. Collapse predicted labels to the tissue's broad-lineage vocabulary via `map_to_*_broad()`
   → consensus prediction.
4. Compute six external ground-truth metrics:
   - `external_leiden_ari`, `external_leiden_nmi` — Leiden partition vs ground truth
   - `external_homogeneity`, `external_completeness` — same, `sklearn.metrics`
   - `external_celltypist_broad_accuracy`, `external_celltypist_broad_macro_f1` —
     CellTypist consensus vs ground truth

Then, across the 90 trials:

5. Aggregate into `trial_objective_facs_concordance.csv` (one row per trial).
6. Correlate internal metrics (`yield_score_target`, `balanced_score_gmean`, component
   scores) against the six external metrics under all three regimes.
7. Emit granularity-confound diagnostics (cluster count vs external, resolution vs external,
   internal vs external scatters).
8. Run **positive-control baselines**: re-score the same 90 trials with four purely
   granularity-driven surrogate objectives (`n_clusters`, `-n_clusters`, `resolution`,
   `-resolution`) and report their partial ρ against the same six external metrics.
9. Render all figures.

Design notes:

- Columns follow the fixed six-metric ordering in `EXTERNAL_METRIC_ORDER`.

- Colour scale is symmetric diverging (`vmin=-1, vmax=1, center=0`) so sign flips

| Error | Cause | Fix |
|---|---|---|
| `FileNotFoundError: Missing raw correlation CSV` | Main pipeline not yet run for this tissue | Run `objective_to_facs_concordance_1argu.py` first |
| `ValueError: ... no rows remain` | Non-standard column names | Extend the `find_column()` fallback list |
| All-NaN heatmap | `spearman_rho` parsed as string | Check for non-numeric characters in the CSV |
| Ugly internal row labels | `INTERNAL_LABELS` incomplete | Add a human-readable mapping |

## 4. Analysis 3 — Multi-seed optimizer comparison

**Script:** `multi_seed_optimizer_comparison.py`
**Output:** `data/multiseed_optimizer_comparison/pbmc/`
**Figure:** Supplementary Fig. S12 (panels a–f)

### 4.1 Purpose

Aggregates **eight independent Bayesian-optimization runs per optimizer**
(scBOA-GP, Optuna-TPE, Random search) on the PBMC 10x 3k dataset, computes per-seed best
scores, pairwise Wilcoxon signed-rank tests, and mean ± 95 % CI convergence traces.

Seeds used: `1, 43, 44, 45, 50, 80, 100, 202`.
Seed 42 is **not** part of this replication set — it corresponds to the original single-seed
scBOA-GP result reported in the main text (Fig. S24) and is treated as a 9th independent
observation rather than pooled here.

Budget: 90 function evaluations per (optimizer, seed) — the equal-budget contract.

### 4.2 What it does / does not do

Per `(optimizer, seed)`:

1. Locate the `*_yield_scores_report.csv` produced by the upstream Stage-1 pipeline
   (`Bayesian_Optimization_Multi_fidelity_full_11.py`).
2. Concatenate all internal acquisition strategies in `(strategy, call_number)` order →
   exactly one convergence trace of length ≤ `--max_trials`.
3. Extract the argmax configuration and its parameter vector (`n_hvg`, `n_pcs`,
   `n_neighbors`, `resolution`, plus `n_consensus_labels`, `mean_confidence`,
   `silhouette_score`).
4. Compute best-so-far cumulative maxima.

At aggregation: between-seed mean / SD / min / max / CV of `best_score`; pairwise Wilcoxon
signed-rank tests on paired-seed best scores; trial-by-trial mean ± 95 % CI of the
best-so-far trace; CV of every selected parameter across seeds.

It does **not** run the optimization itself, does **not** enforce a common seed schedule
across optimizers (seed labels are opaque identifiers), and does **not** re-run CellTypist —
all downstream biological quantities are read from the upstream yield-score reports.

**Budget note.** Within a single seed, the Stage-1 pipeline runs three GP acquisition
sub-strategies (Exploit / BO-EI / Explore) and returns the best configuration across all
three; this script treats that returned best as **one observation per seed**, matching the
main-text single-seed reporting. Optuna-TPE and Random search have no ensemble structure
and run at their native 90-trial budget per seed.

### 4.3 Expected directory layout

```
repeat_test/
├── 1PBMC_matched_CASonly90/          # scBOA-GP, seed 1
│   └── stage_1_bayesian_optimization/
│       └── FACS_PBMC_matched_CASonly90_biological_balanced_yield_scores_report.csv
├── 43PBMC_matched_CASonly90/         # scBOA-GP, seed 43
├── ...
├── 1PBMC_matched_CASonly_random90/   # Random search, seed 1
├── ...
├── 1PBMC_matched_balanced_optuna90/  # Optuna-TPE, seed 1
└── ...
```

Directory names are a caller-side convention only; the script does not parse them. It only
requires that each `--*_stage_dirs` list has one directory per seed, aligned to `--seeds`,
and that each directory contains exactly one `*_yield_scores_report.csv`
(files containing `refinement_depth` are excluded).

### 4.4 Required CSV columns

| Column | Purpose |
|---|---|
| `yield_score_target` (or `balanced_score_gmean`) | Objective per trial; auto-inferred if `--objective_col` omitted |
| `call_number` | Trial index within an acquisition strategy; auto-generated if missing |
| `strategy` | Acquisition label (Exploit / BO-EI / Explore / TPE / Random); auto-filled if missing |

Optional (used for the parameter summary and CV bar plot, silently skipped if absent):
`n_hvg`, `n_pcs`, `n_neighbors`, `resolution`, `mean_cas`, `weighted_mean_cas`,
`simple_mean_cas`, `mean_mcs`, `mean_f1`, `mean_confidence`, `silhouette_score`,

### 4.5 Invocation

```bash

  --gp_stage_dirs \
      $RT/{1,43,44,45,50,80,100,202}PBMC_matched_CASonly90/stage_1_bayesian_optimization \
  --random_stage_dirs \

  --optuna_stage_dirs \
```

| Flag | Required | Meaning |
|---|---|---|

| `--random_stage_dirs` | yes | Same, Random search |

**`pairwise_wilcoxon_best_score.csv` columns**

| Column | Meaning |
|---|---|
| `optimizer_A`, `optimizer_B` | Compared optimizers |
| `n_paired_seeds` | Seeds present in both |
| `mean_diff_AminusB` | Paired mean difference; positive ⇒ A better |
| `statistic` | Wilcoxon *W* (sum of positive-signed ranks; exact mode when n ≤ 25) |
| `p_value` | Two-sided |
| `seeds` | Comma-separated seed labels used |

`W = 0.0` in a significant comparison means the direction of the difference is **unanimous**
across all paired seeds — the strongest sign-consistency signal available at n = 8.

**`convergence_mean_ci.csv` columns**

| Column | Meaning |
|---|---|

| `eval_index` | 1-based trial index within the 90-trial window |
| `n_seeds` | Seeds contributing at this index (8 everywhere) |
| `mean`, `std` | Mean and sample SD of best-so-far across seeds |
| `ci95_low`, `ci95_high` | Student-*t* 95 % CI on the mean |

### 4.8 Plot interpretation

- **Fig. S12a** (`best_score_boxplot`): per-seed dots on optimizer-level boxes, with pairwise
  Wilcoxon brackets. Dots are colour-coded and labelled by seed so a given seed can be traced
  across all three optimizer columns — the visual counterpart of *W* = 0.0.
- **Fig. S12e** (`convergence_curve_mean_ci`): mean best-so-far with a **Student-*t* 95 % CI
  band** (not SEM), so the band is honest about n = 8.
- **Fig. S12f** (`param_variance_barplot`): CV = SD/mean of each selected parameter across
  seeds, grouped by optimizer. Low CV under scBOA-GP and Optuna-TPE relative to Random
  supports the parameter-stability claim.


Algorithm: a **768-combination grid** (4 gene-set sizes × 2 neighbour methods × 2 metrics ×
4 `n_pcs` × 3 `k_nn` × 4 resolutions), 20 stratified subsamples per combination, then a
random-intercept linear mixed model (`statsmodels.MixedLM`) whose marginal ARI predictions
rank the combinations.

(long format, `n_subsamples` × 768 rows), `bp_sciaraffa_marginal_predictions.csv`,
`bp_sciaraffa_lmm_summary.txt`.

> **Reimplementation note.** The original paper ships no public code. This implementation
> follows the published supplementary specification with two documented simplifications:
> (i) 20 subsamples instead of 100 (`--n_subsamples`); (ii) `statsmodels.MixedLM` (Gaussian
> LMM) instead of R `robustlmm::rlmer`. With 20 stratified subsamples the marginal-mean
> ranking is insensitive to the robust/non-robust distinction on all three benchmark
> datasets. The full 768-combination grid is preserved exactly.

### 5.15 Documented exclusion — SCIPIO-86 / Fang et al. 2024

We consider Fang et al. (*Genome Biol.* 2024) an important reference and evaluated it
seriously for inclusion, but excluded it for the following documented reasons.

Fang2024 is a fundamentally different paradigm: a **supervised meta-learner** that trains
dataset-specific regressors mapping raw-count summary statistics to expected pipeline ARI.
We cloned the authors' repository (`camlab-bioml/beyond_benchmarking_analyses`) and confirmed:

1. the repository ships analysis and training code only, with **no pre-trained model artefact**
   (`.pkl`, `.joblib`, `.h5`, `.pt`, `.RDS`) distributed;
2. the Zenodo deposit (record 11402899) contains only the training Snakemake workflow, not the
   trained model weights;
3. applying the method therefore requires re-executing the authors' Snakemake pipeline over
   100 EBI SCXA datasets × 324 pipeline combinations (**32,400 pipeline runs**), with several
   rules requesting 30–130 GB RAM — infeasible within the revision timeline.

We instead cite Fang2024 in the Discussion as a complementary paradigm — for example, a
Fang-style meta-learned prior could warm-start scBOA's Gaussian process — and note this as
future work. A fair head-to-head benchmark will become possible once the trained model
artefact is deposited.

## 6. Benchmark datasets — three heterogeneity regimes

Three independent tissue-benchmark generators produce a **common output schema**, so scBOA
and all 14 baselines consume them with identical hyperparameters.

| Script | Language | Dataset | Regime |
|---|---|---|---|
| `real_pbmc_ground_truth.R` | R | Zheng 10x FACS-sorted PBMC | I — low within-class heterogeneity |
| `prepare_pancreas_ground_truth.R` | R | Baron pancreas (Bioconductor `scRNAseq`) | II — medium |
| `prepare_tissue_ground_truth.R` + `subsample_heart_10x.py` | R + Python | Litviňuková human heart (HCA Heart Cell Atlas) | III — high |

Each emits:
- a **10x MTX v3 triplet** (`matrix.mtx.gz`, `features.tsv.gz`, `barcodes.tsv.gz`),
- `ground_truth_metadata.csv`,
- `dataset_summary.txt` (composition, filters, provenance).


The raw Sanger `.h5ad` is ~15 GB and mixes 10x-cell / 10x-nuclei / V2 / V3 chemistries, so the
atlas is first fetched, then filtered to a technically homogeneous subset.

**Step 3a — fetch raw `.h5ad`**

Downloads/caches `global_raw.h5ad` from
`https://cellgeni.cog.sanger.ac.uk/heartcellatlas/data/global_raw.h5ad`
and exports the full atlas (~490k cells, all chemistries). The same script also supports
`--dataset sikkema_human_lung`, the Bioconductor pancreas/brain datasets,
`--counts_layer counts` (when `X` is log-normalized), and `--h5ad_path` for a local file.

**Step 3b — filter + stratified subsample**

```bash

  --h5ad_path /path/to/litvinukova_heart_ground_truth/global_raw.h5ad \
  --output_dir /path/to/litvinukova_heart_ground_truth/litvinukova_heart_nuclei_v3_10k_top7 \

  --min_cells_per_label 100 --top_n_labels 7 \
  --drop_labels doublets NotAssigned
```

Three stages: (1) technical filters (`source == Nuclei`, `version == V3`, `Used == Yes`);
(2) label filters (drop `doublets`/`NotAssigned`; optional `--min_cells_per_label`,
`--top_n_labels`); (3) stratified subsample to `--n_cells` with proportional per-class quotas
(small classes retained in full).

Heart metadata additionally exports multi-level annotations for granularity-concordance
analysis: `ann_level_1` (13 broad classes, from `cell_type`), `ann_finest_level`
(67 classes, from `cell_states`), plus `source`, `version`, `Used`, `donor`, `region`,
`sample`.

### 6.4 Unified output schema

`10x_matrix/` — standard 10x MTX v3 triplet, loadable by `scanpy.read_10x_mtx()`,
`Seurat::Read10X()`, `DropletUtils::read10xCounts()`.

`ground_truth_metadata.csv`:

| Column | Required | Description |
|---|---|---|
| `cell_id` | yes | Matches `barcodes.tsv.gz` |
| `ground_truth_cell_type` | yes | Externally curated label |
| `dataset` | yes | Source dataset name |
| `external_label_column` | yes | Which source column was used |
| `ann_level_1`, `ann_finest_level` | heart only | Multi-level annotations |

`dataset_summary.txt` — human-readable provenance: source, filters, cell/gene counts,
per-label counts, output paths.

### 6.5 Regime placement

The three datasets span a monotone gradient of intrinsic within-class transcriptional
heterogeneity, quantified by the partial correlation between ARI (vs ground truth) and
annotation quality (consensus CellTypist agreement) after controlling for cluster count:

| Regime | Dataset | Within-class heterogeneity | Expected scBOA behaviour |
|---|---|---|---|
| I | PBMC (Zheng, 5k) | Low | Wins on ARI **and** annotation quality |
| II | Baron pancreas (8.5k) | Medium | Wins on annotation quality; loses ARI to methods choosing coarser partitions |
| III | Litviňuková heart (10k) | High | Continues optimising annotation quality; ARI decouples from biological correctness |

This gradient is the empirical basis for Analysis 1.

### 6.6 Labelling caveat

All labels are **externally curated annotations** supplied by the original study or by FACS
pre-sorting. They are used as a gold-standard external reference, **not** as absolute
biological ground truth. This distinction applies uniformly across all three regimes.

### 6.7 Reproducibility

- PBMC: deterministic given `set.seed(42)` in `real_pbmc_ground_truth.R`.
- Pancreas: deterministic given `--seed 123` and the pinned Bioconductor `scRNAseq` version.
- Heart: deterministic given `--seed 0` in `subsample_heart_10x.py` and the SHA-256 of the
  cached `global_raw.h5ad`.

Record the cached `.h5ad` SHA and the R/Python `sessionInfo()` for a full audit trail.

### 7.1 Design

### 7.4 Level-of-analysis caveat (important)

- Predicted labels in Stage 1 are **cluster-consensus** labels
  (`ctpt_consensus_prediction`), broadcast to all cells in a Leiden cluster.
- Confidence values are **per-cell** CellTypist max posteriors (`ctpt_confidence`), which are
  *not* broadcast by the consensus step.

This mixed indexing is intentional and matches the Fig. S7 legend. Do **not** compare the
destination percentages here (e.g. CD14_mono 94.0 %) with the per-cell top-1 destination
percentages in Fig. S1 (e.g. CD14_mono 40.3 %): they describe the same misassignment event at
two different analytical levels.

### 7.7 Scope and caveats

- This pipeline analyses the **full scBOA output**. Cluster-consensus labels dominate the
  destination distribution; per-cell top-1 CellTypist destinations are more dispersed and are
  analysed by a separate direct-annotation pipeline (Fig. S1).
- Most no-B B-cell errors carry **low** per-cell confidence, so this benchmark is a
  low-confidence partial-mismatch case rather than a high-confidence silent-failure case.
  Silent-failure sensitivity of scBOA cluster-level QC (R1/R2/R3) is evaluated in the separate
  HEK293T spike-in benchmarks and is **not** measured here.
- The Wilcoxon test is a **cell-level paired** test over the same 500 B cells under two
  references. It quantifies a within-cell shift in CellTypist confidence and is not a test of
  independent biological replication. *P*-values in
  `B_cell_paired_confidence_test.csv` are configuration- or cell-paired, not independent
  biological replicates.
